# ADR 0005: 최근 비교 가능한 거래만 순위에 사용

- 상태: Accepted
- 일자: 2026-07-24
- 보완 결정: ADR 0003, ADR 0004의 rolling 후보 및 비교 정책

## Context

최근 7일에 등록된 거래라도 계약일은 수년 전일 수 있다. 또한 같은 단지와
정확히 같은 전용면적의 직전 거래를 선택하더라도 그 계약이 지나치게 오래되면
상승률과 하락률이 현재 시장의 가격 변화를 설명하지 못한다. 실제 서울
상승률 순위에는 2026년 거래와 2014년 직전 거래를 비교한 항목이 노출됐다.

신규, 최고가, 신고가, 상승, 하락이 서로 다른 현재 거래 집합을 사용하면
화면에서 같은 “최근 7일”로 보이더라도 지표 간 해석이 일관되지 않는다.

## Decision

등록일 기반 다섯 section은 기존 최근 7일 등록일/계약일 fallback 조건에 더해
현재 `deal_date`가 `period_end - 1 calendar month .. period_end` 안에 있는
거래만 사용한다.

- 신규는 이 공통 후보를 등록일/fallback 날짜 최신순으로 정렬한다.
- 최고가는 이 공통 후보를 거래금액순으로 정렬한다.
- 신고가, 상승, 하락은 같은 `complex_id`와 정확히 같은 `excl_area`만
  비교한다.
- 비교 거래는 현재 계약일보다 앞선 가장 가까운 계약일이며, 현재 계약일과
  최대 6 calendar months 차이여야 한다.
- 직전 계약일에 여러 거래가 있으면 기존 deterministic median 대표 거래를
  사용한다.
- 신고가는 최근 직전 거래 조건을 통과한 경우에만 과거 전체 최고 거래금액을
  갱신했는지 판정한다.

공개 URL과 response shape는 바꾸지 않는다. Web은 비교 행에 직전 또는
이전 최고 계약일을 함께 표시하고 기준 안내에 1개월/6개월 조건을 명시한다.

## Consequences

- 장기간 거래 공백에서 생긴 과도한 상승률·하락률은 순위에서 빠진다.
- 다섯 지표의 현재 거래 모집단이 최근 계약이라는 공통 조건을 갖는다.
- 신고가는 단순 직전 거래 상승과 구분되는 과거 최고가 갱신 의미를 유지한다.
- 기존 snapshot은 수정하지 않으며 다음 정상 `DAILY/NATIONWIDE` 실행이 새
  기준의 immutable rolling snapshot을 발행한다.
- `/latest`, 원천 적재, source identity dedupe, 취소 근거는 변경하지 않는다.
